### D-001 폰 → gateway 전송: WebSocket 바이너리
- **선택지**
  - A. WebSocket + JPEG 프레임 — 구현이 단순하고 프레임 단위 타임스탬프를 붙이기 쉬움. 대역폭은 큼(640x480·15fps 기준 대략 0.5~1.5MB/s)
  - B. WebRTC — 지연과 압축 면에서 유리하지만 서버에서 aiortc로 디코딩해야 하고, 시그널링과 NAT 처리로 복잡도가 큼
- **결정**: A. 폰은 바이너리(헤더 + JPEG)로 보내고, gateway가 `jpeg_base64` JSON으로 바꿔 Redis에 publish합니다.
- **이유**: 같은 LAN이고 5인 팀 일정이 있어 단순함을 우선했습니다. 흐름 제어(D-002)로 지연 누적을 막습니다.

### D-002 흐름 제어: 최대 2프레임 in-flight
- **결정**: ack 없이 동시에 최대 2장까지 보내고, ack 대기 중인 프레임이 2장이면 새 프레임은 버립니다. 값은 `MAX_INFLIGHT_FRAMES`로 조절합니다.
- **이유**: 1장씩 주고받으면 RTT만큼 처리량이 떨어집니다. 큐에 쌓으면 지연이 누적됩니다. 2장이 처리량과 지연의 균형점입니다.

### D-003 지연시간 측정: gateway 기준 시계 동기화
- **선택지**
  - A. ping/pong으로 폰·PC의 시계 차이를 추정해 전체 구간(촬영 → 표시) 측정
  - B. 서버 내부 구간과 기기별 RTT만 측정
- **결정**: A. 2단계에서는 추정까지 구현하고, 화면 표시는 3단계에서 붙입니다.
- **이유**: 시연에서 "촬영부터 표시까지" 지연을 정확히 보여주기 위해서입니다.

### D-004 스키마 확장
- **결정**
  - `trace{capture, gw_recv, vision_done, gesture_done}`: 모든 필드 Optional
  - `mirror`: 전면 카메라일 때만 x를 반전하기 위한 값. 명세는 셀카 기준이라, 후면 카메라에서도 반전하면 좌우가 뒤집힘
  - `seq`, `stroke_id`: 1단계 구현 중 추가. `seq`는 ack와 프레임 버림 통계용, `stroke_id`는 새 선 시작과 stroke 단위 실행 취소용
  - 모르는 필드는 무시(`extra="ignore"`)해서 앞으로 필드를 추가해도 호환됨

### D-005 손 인식: MediaPipe Tasks API + Python 3.11
- **결정**: `HandLandmarker`(VIDEO 모드), Python 3.11, **세션별 인스턴스**(VIDEO 모드는 타임스탬프가 단조 증가해야 함), `NUM_HANDS` 기본 1.
- **확인 결과**: MediaPipe 1.2.0에는 예전 `mp.solutions`가 없어졌습니다. Tasks API를 고른 것이 맞았습니다.

### D-006 QR 주소
- **결정**: 기본은 `.env`의 `PUBLIC_HOST`입니다. PC가 LAN IP로 접속했다면 요청 Host를 씁니다. `gen_cert.py`는 LAN IP 후보 목록을 보여주고 **사용자가 고르게** 하며, 고른 IP를 인증서 SAN과 `PUBLIC_HOST`에 반영합니다.
- **이유**: 컨테이너는 PC의 LAN IP를 알 수 없습니다. 또 Windows에는 Docker/WSL/VPN 가상 어댑터가 많아 자동으로 고르면 틀리기 쉽습니다.

### D-007 프레임 처리 정책
- **결정**: vision은 세션별 최신 프레임 슬롯만 처리하고 밀린 프레임은 버립니다. gesture는 디바운스 상태가 있으므로 모든 메시지를 순서대로 처리합니다.

### D-008 좌표 변환 기준
- **결정**: 반전과 중앙 `ACTIVE_AREA` 매핑은 gesture가 기준입니다. `landmarks`는 원본 좌표로 두고, PC는 `/api/config`의 파라미터로 같은 변환을 적용해 뼈대를 그립니다. 프레임 비율 반영은 D-018.
- **이유**: 변환을 한 곳에서 정의해야 커서와 뼈대가 어긋나지 않습니다.

### D-009 OpenCV 단일 패키지
- **결정**: MediaPipe가 의존하는 `opencv-contrib-python`만 씁니다. headless나 일반 패키지를 섞지 않습니다.
- **이유**: 여러 OpenCV 패키지가 함께 설치되면 `cv2`가 서로 덮어써서 깨집니다.

### D-010 헬스체크
- **결정**: gateway는 `/health`를 제공합니다(Redis ping + 다른 서비스 하트비트). vision과 gesture는 Redis 키 `health:{service}`(TTL)를 주기적으로 갱신합니다.
- **이유**: HTTP 서버가 없는 서비스도 "Redis 연결 정상 + 루프 생존"을 한 번에 확인할 수 있고, gateway가 전체 상태를 모아 보여줄 수 있습니다.

### D-011 서비스 패키지 이름
- **결정**: 처음 계획했던 `app/` 대신 `gateway/`, `vision/`, `gesture/`를 씁니다.
- **이유**: 이름이 같으면 루트에서 `pytest`를 한 번에 돌릴 때 import가 충돌합니다.

### D-012 그림판 시각 요소
- **결정**
  - 기본 시각 요소는 **손 뼈대 오버레이**입니다. 손 옆에 제스처 라벨(✏️ 그리기, ✌️ 이동, ✋ 지우개, ✊ 대기)을 표시합니다.
  - 상태별로 표현을 바꿉니다: draw일 때는 검지 끝을 강조하고, move(펜 든 상태)일 때는 뼈대를 흐리게 그립니다.
  - 폰 영상 PiP는 **선택 기능이고 기본값은 꺼짐**입니다. 켜기/끄기와 위치 변경이 가능해야 하고, **꺼져 있으면 PC로 영상을 보내지 않습니다.**
- **이유**: Zoom 시청자는 손을 볼 수 없으므로 뼈대와 라벨로 동작을 전달합니다. PiP 영상 전송은 같은 노트북의 부하를 늘리므로 필요할 때만 켭니다.

### D-013 시연 성능 조절
- **결정**: 해상도, fps, `NUM_HANDS`, JPEG 품질을 모두 `.env`로 조절할 수 있게 합니다. FPS·지연시간 표시는 크게, 켜고 끌 수 있게 하고, 시연 모드 토글을 둡니다.
- **이유**: Zoom이 함께 도는 CPU 전용 노트북에서 시연 직전에 바로 조정하기 위해서입니다.

### D-015 PiP 바이너리 형식
- **배경**: 초안 계약은 "PiP = JPEG 바이트"였지만, PC는 셀카 영상을 좌우 반전하려면 `mirror`를 알아야 합니다. 2단계에는 vision이 없어 `landmarks.mirror`도 받을 수 없습니다.
- **선택지**
  - A. 폰 프레임과 같은 형식 `[4B 길이][JSON {ts, seq, mirror, trace}][JPEG]` — 프레임 단위로 정확하고, 3단계에서 PiP 지연 표시에도 쓸 수 있음. canvas가 헤더를 파싱해야 함
  - B. 바이너리는 순수 JPEG로 두고 `status`에 `mirror` 추가 — 필드만 추가하면 되지만, 카메라 전환 순간 1~2프레임이 어긋날 수 있음
- **결정**: A.

### D-016 WebSocket 세션 규칙
- **결정**
  - `POST /api/sessions`로 만들지 않았거나 만료된 세션으로 `/ws/pc`·`/ws/mobile`에 접속하면 수락 직후 close 4404로 닫습니다(수락 전에 닫으면 브라우저가 close 코드를 받지 못함).
  - 같은 세션에 폰이 또 접속하면 새 연결이 이기고 기존 연결은 close 4409로 닫습니다. PC는 여러 개 허용하고 PiP 상태는 연결마다 둡니다.
  - 연결이 살아 있는 동안 ping 주기마다 `session:{sid}` TTL을 연장합니다(시연 중 만료 방지).
- **이유**: 오타 난 세션 ID로 붙어도 조용히 동작하는 것을 막습니다. 폰 새로고침·네트워크 재접속 때 끊긴 소켓이 남아 있어도 바로 다시 붙을 수 있어야 합니다.

### D-017 첫 시계 추정 전 `trace.capture`
- **선택지**: A. `null`로 둠 / B. 환산하지 않은 폰 시각을 그대로 넣음
- **결정**: A. 접속 직후 바로 ping을 보내므로 보통 첫 1~2프레임만 해당합니다. B는 시계 차이만큼 틀린 값이 섞여 지연 통계를 망가뜨립니다.

### D-018 세로 프레임
- **배경**: 폰을 세로로 들면 480x640 프레임이 갑니다(폰 페이지 PRD Q1). 기존 매핑은 비율을 몰라 x·y를 따로 0~1로 늘렸고, 세로 영상에서는 손으로 그린 원이 가로로 약 1.8배 늘어난 타원이 됐습니다.
- **선택지**
  - A. 폰이 항상 가로 4:3으로 잘라 보냄 — 하류는 그대로지만 세로로 들면 보이는 범위가 좁고 폰 페이지 수정 필요
  - B. 세로 허용: 프레임 크기를 메시지에 싣고 gesture가 비율을 유지해 매핑
  - C. 코드는 그대로 두고 "가로 거치" 규칙만 둠
- **결정**: B.
  - `FrameMsg`·`LandmarksMsg`에 `width`·`height`(Optional) 추가. gateway가 JPEG SOF 헤더에서 읽고(디코드 없음), vision이 그대로 옮깁니다. 폰 페이지는 변경 없음.
  - gesture 중앙 영역 = 프레임 안 가장 큰 캔버스 비율(`CAMERA_WIDTH:HEIGHT`) 사각형 × `ACTIVE_AREA`. 가로 4:3이면 기존 식과 같습니다.
  - 값이 없으면 기존 동작이라 이전 fixture·도구와 호환됩니다.
- **영향**: 3단계 그림판 뼈대 오버레이는 같은 식을 써야 합니다([04-gestures.md](04-gestures.md) ⑤).
