# 1. 프로젝트 개요

## 한 줄 소개
휴대폰 카메라로 손을 찍으면 PC 브라우저 그림판에 손 뼈대(21개 랜드마크)가 표시되고, 손 모양에 따라 그리기·지우기 등을 원격으로 제어하는 웹 서비스입니다.

## 사용자 흐름
1. PC 브라우저에서 그림판 페이지에 접속하면 세션이 생성되고 QR 코드가 표시됩니다.
2. 휴대폰으로 QR을 스캔하면 카메라 페이지가 열리고 프레임 스트리밍이 시작됩니다.
3. PC 화면에 손 뼈대 오버레이가 나타나고, 제스처에 따라 그림이 그려집니다.

```
[PC] 그림판 접속 → QR 표시 ──스캔──▶ [폰] 카메라 페이지 → 프레임 전송
                                                    │
[PC] 손 뼈대 + 제스처 라벨 + 그림 ◀── 인식 결과 ◀────┘
```

## 기본 제스처
| 손 모양 | 동작 |
|---|---|
| 검지만 | 그리기 |
| 검지 + 중지 | 이동 (펜 들기) |
| 주먹 | 대기 |
| 손바닥 | 지우개 |
| 엄지 + 검지 집기 | 색상 선택 (원형 팔레트) |
| 엄지만 세우기 | 실행 취소 |

자세한 규칙은 [04-gestures.md](04-gestures.md)를 보세요.

## 시연 형태
- 시연은 집에서 하고, **Zoom 화면 공유로 PC 브라우저 창을 보여주는 방식**입니다.
- **시청자는 발표자의 손을 볼 수 없습니다.** 그래서 그림판의 **손 뼈대 오버레이와 제스처 라벨**이 손동작을 전달하는 주 수단입니다. 폰 카메라 영상(PiP)은 선택 기능입니다.
- Zoom이 같은 노트북에서 함께 돌아가므로 성능 여유가 적습니다 → [09-demo.md](09-demo.md)

## 개발 환경 제약
| 항목 | 내용 | 영향 |
|---|---|---|
| 노트북 | AMD Ryzen 7 5700U, RAM 16GB, AMD 내장 그래픽 | **CUDA 불가, 모든 추론은 CPU** |
| OS | Windows + Docker Desktop(WSL2), VS Code | 줄바꿈 LF 강제, 컨테이너에서 웹캠 사용 불가 |
| 네트워크 | 폰과 PC는 같은 와이파이 | AP 격리 시 폰 핫스팟 사용, IP가 바뀌면 인증서 재발급 |
| 브라우저 | 폰 카메라(`getUserMedia`)는 HTTPS 필수 | 자체 서명 인증서로 HTTPS 제공 |

## 범위
- **포함**: 1~5단계([06-roadmap.md](06-roadmap.md)). 손 뼈대 표시, 그리기·이동·대기·지우개, 색상 변경, 실행 취소, PNG 저장, FPS·지연시간 측정.
- **제외(현재)**: WebRTC, GPU 추론, 여러 사용자가 한 캔버스를 함께 쓰는 기능, 인터넷 배포(같은 LAN 전용).
